# Проверка на живом Keitaro

Панель `https://tlgk.host/admin`, API `https://tlgk.host/admin_api/v1`, свой ключ из «Профиль → API ключи».

## 1. Кампания и потоки

`POST /api/campaigns` с `{"name":"campaign1","geo":"AU","offer_id":25327}` → кампания **212056**
`test_vorobev_campaign1` (alias такой же), ссылка `https://kylovoa.com/test_vorobev_campaign1`,
`domain_id 1813` / `group_id 9799` / `traffic_source_id 836`.
Сырые ответы: [campaign_212056.json](campaign_212056.json), [streams_212056.json](streams_212056.json).

| # | id | name | schema | редирект / офферы | фильтр |
|---|---|---|---|---|---|
| 1 | `1311120` | Google | `redirect` | `action_options.url = https://www.google.com/` | `country accept ["AU"]` |
| 2 | `1311121` | Offers | `landings` | `25327: 34`, `24800: 33`, `10184: 33` (сумма 100) | — |

`action_options.url` заполнен явно: в этой сборке Keitaro redirect-поток без него не работает
(у многих кампаний в аккаунте поле `null`). В обоих потоках `collect_clicks: true`.

## 2. Редактор офферов (через UI)

`[(25327, 100)]` → «＋ Добавить оффер» `24800` → `[(25327, 50), (24800, 50)]` → «Удалить» `24800`
(с подтверждением) → `[(25327, 100)]` → добавить `24800` (60 %) и `10184` (без веса) →
`[(25327, 34), (24800, 33), (10184, 33)]`, сумма ровно 100. Каждое изменение — один
`PUT /streams/1311121` с полным массивом `offers`, запрос и ответ видны на вкладке «Журнал API».

Вторая кампания **212058** `test_vorobev_campaign2_ro` создана для гео `RO` и оффера `24800`.

## 3. Статистика

```json
{"range":{"interval":"all_time"},"dimensions":["stream_id","offer_id"],
 "metrics":["clicks","campaign_unique_clicks","bots"],
 "filters":[{"name":"campaign_id","operator":"EQUALS","expression":212056}]}
```

Сначала `{"rows": [], "total": 0}` — трафика не было; после захода краулера все три уровня сошлись:

```
report/build campaign_id=212056          → clicks 5, campaign_unique_clicks 0, bots 2
report/build [stream_id,offer_id]        → 25327: 3/0/1, 10184: 2/0/1
GET /api/campaigns/212056                → кампания 5/0/2 · Offers 5/0/2 · Google 0/0/0
```

Суммы по офферам дают поток, по потокам — кампанию. Метрики `uniques` в API нет, правильное имя
`campaign_unique_clicks`. Сверка на чужой кампании с трафиком (`test_walrus_campaign1`, 209551,
только чтение): поток `1298691` — 4/1/3, офферы `24800` — 2/0/2 и `25327` — 2/1/1; ровно это же
показывает `GET /api/campaigns/209551` и список кампаний.

## 4. Гео и повторное имя

* `geo: "AU, RO"` (кампания 212471) → фильтр `{"country","accept",["AU","RO"]}`; после проверки удалена.
* Повторный `POST` с занятым именем раньше давал 502 и текст Keitaro (`422 Alias/Name has already used`).
  Теперь — один ретрай с суффиксом: `212476 test_vorobev_dup_probe2` → `212477 test_vorobev_dup_probe2 b115`,
  в журнале `campaign.create.duplicate_retry`. Обе проверочные кампании удалены.
* 4xx Keitaro отдаются как `400` с его текстом, `502` — только сеть и 5xx.

## 5. Негативные сценарии

| Сценарий | Результат |
|---|---|
| `geo: "AUS"` / `offer_id: 999999` / пустое тело | `400` «нужен ISO-3166 alpha-2…» / `400` «Оффер 999999 не найден» / `422` pydantic |
| пустое название в UI | браузер блокирует `required`, запроса в сеть нет, форма остаётся открытой |
| добавить существующий оффер / удалить последний | тосты «Оффер 25327 уже есть в потоке» / «Нельзя удалить последний оффер потока…», в Keitaro ничего не уходит |
| `PUT` офферов в redirect-поток | `400` «Офферы можно менять только в потоке с типом «landings»» |
| `PUT …/offers` с `offers: []` | **был баг:** Keitaro принимал пустой массив. Теперь `400` «Нельзя оставить поток без офферов…» + тест, офферы 212056 восстановлены |
| неверный `KEITARO_API_KEY` | плашка `API: ошибка 401`, баннер с причиной и подсказкой ключа, список с текстом «проверьте KEITARO_API_KEY», приложение не падает; с закэшированными справочниками форма продолжает работать |
