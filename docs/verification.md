# Проверка на живом Keitaro

Панель: `https://tlgk.host/admin` · API: `https://tlgk.host/admin_api/v1` · ключ из «Профиль → API ключи».

## 1. Кампания создана через наш сервис

`POST http://127.0.0.1:8000/api/campaigns` с телом `{"name":"campaign1","geo":"AU","offer_id":25327}`.

| Поле | Значение |
|---|---|
| id | `212056` |
| name / alias | `test_vorobev_campaign1` |
| ссылка | `https://kylovoa.com/test_vorobev_campaign1` |
| domain_id / group_id / traffic_source_id | `1813` / `9799` / `836` |

Сырой ответ `GET /campaigns/212056` — в [campaign_212056.json](campaign_212056.json).

## 2. Потоки

`GET /campaigns/212056/streams` (полный ответ — [streams_212056.json](streams_212056.json)):

| # | id | name | schema | редирект | фильтр | офферы |
|---|---|---|---|---|---|---|
| 1 | `1311120` | Google | `redirect` | `action_options.url = https://www.google.com/` | `country accept ["AU"]` | — |
| 2 | `1311121` | Offers | `landings` | — | — | `25327: 34`, `24800: 33`, `10184: 33` (сумма 100) |

Ключевые фрагменты ответа:

```json
{
  "id": 1311120, "name": "Google", "position": 1, "schema": "redirect",
  "action_type": "http", "action_options": {"url": "https://www.google.com/"},
  "collect_clicks": true,
  "filters": [{"name": "country", "mode": "accept", "payload": ["AU"]}]
}
```

```json
{
  "id": 1311121, "name": "Offers", "position": 2, "schema": "landings",
  "offers": [
    {"offer_id": 25327, "share": 34},
    {"offer_id": 24800, "share": 33},
    {"offer_id": 10184, "share": 33}
  ]
}
```

> `action_options.url` в потоке «Google» заполнен явно — в этой сборке Keitaro redirect-поток без него
> не работает. У многих кампаний в аккаунте это поле `null`.

## 3. Редактор офферов (через UI, реальные запросы)

1. Старт: `[(25327, 100)]`.
2. «＋ Добавить оффер» → `24800` → после нормализации `[(25327, 50), (24800, 50)]`.
3. «Удалить» `24800` (подтверждение в диалоге) → `[(25327, 100)]`.
4. Добавление `24800` (60 %) и `10184` (без веса) → `[(25327, 34), (24800, 33), (10184, 33)]` — сумма ровно 100.

Каждое изменение — один `PUT /streams/1311121` с полным массивом `offers`; запрос и ответ видны
на вкладке «Журнал API» (см. `docs/screenshots/04-logs.png`).

Вторая кампания `test_vorobev_campaign2_ro` (id `212058`) создана для проверки гео `RO` и оффера `24800`.

## 4. Статистика

`POST /report/build`:

```json
{"range": {"interval": "all_time"},
 "dimensions": ["campaign"],
 "metrics": ["clicks", "campaign_unique_clicks", "bots"],
 "filters": [{"name": "campaign_id", "operator": "EQUALS", "expression": 212056}]}
```

Ответ у своей кампании сначала был `{"rows": [], "total": 0}` — трафика не было. Потом до 212056 дошли
живые запросы (краулер, домен не резолвится с моей машины), и все три уровня сошлись:

```
POST /report/build  campaign_id=212056                     → clicks 5, campaign_unique_clicks 0, bots 2
POST /report/build  dimensions=[stream_id,offer_id]        → 25327: 3/0/1, 10184: 2/0/1
GET  /api/campaigns/212056                                 → кампания 5/0/2 · Offers 5/0/2 · Google 0/0/0
                                                             офферы: 25327 3/0/1, 24800 0/0/0, 10184 2/0/1
```

Суммы по офферам дают цифру потока, суммы по потокам — кампанию; это же отдаёт `/api/campaigns/{id}`
(поля `clicks/uniques/bots` на каждом из трёх уровней).

Метрика `uniques` в API Keitaro не существует — правильное имя `campaign_unique_clicks`.

Чтобы проверить, что цифры действительно совпадают с Keitaro, я сравнил их на чужой кампании с трафиком
(`test_walrus_campaign1`, id `209551`) — только чтение, без изменений:

```
POST /report/build  dimensions=["stream_id"]
→ 1298691: clicks 4, campaign_unique_clicks 1, bots 3
POST /report/build  dimensions=["stream_id","offer_id"]
→ 24800: 2 / 0 / 2     (оффер уже удалён из потока — в UI не показывается)
→ 25327: 2 / 1 / 1
```

Наш UI для этой же кампании (`GET /api/campaigns/209551`): поток «Offers» — 4 / 1 / 3, оффер `25327` — 2 / 1 / 1,
в списке кампаний (`GET /api/campaigns?only_ours=false&search=walrus`) — 4 / 1 / 3. Совпадает.

## 5. Гео из нескольких стран

Создание с `geo: "AU, RO"` (кампания 212471) дало поток «Google» с фильтром
`{"name": "country", "mode": "accept", "payload": ["AU", "RO"]}`.
После проверки кампания удалена (`DELETE` → 200, `GET` → 404), чтобы не мусорить в аккаунте.
Валидация: `geo: "AUS"` → 400 «нужен ISO-3166 alpha-2», несуществующий оффер → 400.

## 6. Повторное имя кампании

Повторный `POST /api/campaigns` с тем же именем раньше отдавал 502 и текст Keitaro
(`422 Alias/Name has already used`). Теперь сервис ловит эту ситуацию, один раз пересоздаёт кампанию
с суффиксом и пишет `campaign.create.duplicate_retry` в журнал. Живая проверка:

```
POST {"name":"dup_probe2","geo":"AU","offer_id":25327}  → 201 212476 test_vorobev_dup_probe2
повтор того же запроса                                   → 201 212477 test_vorobev_dup_probe2 b115 / ...-b115
```

Обе проверочные кампании (212476, 212477) и 212475 удалены, в аккаунте остались только 212056 и 212058.
Кроме этого, 4xx-ответы Keitaro теперь отдаются как `400` с его текстом, `502` — только сеть и 5xx.

## 7. Негативные сценарии (проверено вживую)

| Сценарий | Результат |
|---|---|
| `POST /api/campaigns` с `geo: "AUS"` | `400`, «Гео-код «AUS» выглядит некорректно: нужен ISO-3166 alpha-2…», кампания не создана |
| `POST /api/campaigns` с `offer_id: 999999` | `400`, «Оффер 999999 не найден в Keitaro» |
| `POST /api/campaigns` с пустым телом | `422` от pydantic (`missing: name, geo, offer_id`) |
| форма с незаполненным названием (UI) | браузер блокирует `required`, **запроса в сеть нет** (сверял счётчик ресурсов), форма остаётся открытой |
| добавить уже существующий оффер (UI) | тост «Оффер 25327 уже есть в потоке», в Keitaro ничего не ушло |
| удалить последний оффер (UI, 212058) | тот же тост «Нельзя удалить последний оффер потока — Keitaro оставит поток пустым», оффер остался |
| `PUT …/flows/<redirect-поток>/offers` | `400`, «Офферы можно менять только в потоке с типом «landings»» |
| `PUT …/offers` с `offers: []` | **найден баг:** Keitaro принимал пустой массив и поток оставался без офферов. Теперь `400` «Нельзя оставить поток без офферов — добавьте хотя бы один» + тест; офферы 212056 восстановлены (34/33/33) |
| неверный `KEITARO_API_KEY` (пустая БД) | плашка `API: ошибка 401`, баннер с причиной и подсказкой ключа, в списке текст «Keitaro отклонил ключ: проверьте KEITARO_API_KEY…», приложение не падает |
| неверный ключ, но есть закэшированные справочники | форма создания остаётся работоспособной (офферы/группы из кэша `dictionary_items`), список кампаний показывает ту же ошибку |

## 8. Уборка за собой

Разведочные кампании `test_probe_study_1794853072` (212027) и `test_vorobev_probe_1794853818` (212050)
удалены через `DELETE /campaigns/{id}` (ответ `200`), повторный `GET` по ним возвращает 404.
Кампании 212056 и 212058 оставлены как результат работы.
